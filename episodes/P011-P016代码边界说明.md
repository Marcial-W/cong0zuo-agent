# P011-P016 代码边界说明

这 6 期只做“从演示版 Agent 到可用版 Agent”的最小代码边界，供脚本反向校验。所有示例默认可直接运行，不需要真实 API Key。

## P011：真实 API 适配器

1. 上一期最后留下的项目状态是什么？  
   第 10 期已经明确：不要直接把 `fake_llm` 散落替换成真实 API，而是先保护模型层边界。
2. 本期只新增哪一个能力？  
   新增 `llm_adapter(prompt)`，让外层代码只调用一个模型入口。
3. 本期出现的函数、变量、文件，前面是否已经讲过？  
   `fake_llm` 前面讲过；`llm_adapter` 是本期新函数；`OPENAI_API_KEY` 是第 10 期铺垫过的环境变量概念。
4. 本期结束后，项目状态变成什么？  
   Agent 具备“真实 API / fake fallback”的模型入口，但默认仍走 `fake_llm`。
5. 下一期要承接哪一个未解决问题？  
   真实模型输出可能不稳定，下一期只检查固定字段。

## P012：结构化结果校验

1. 上一期最后留下的项目状态是什么？  
   已经有了 `llm_adapter(prompt)`，但还不能确认模型返回内容能不能被后续流程使用。
2. 本期只新增哪一个能力？  
   新增 `validate_result(result)`，检查 `summary / concepts / outline` 三个字段。
3. 本期出现的函数、变量、文件，前面是否已经讲过？  
   `summary / concepts / outline` 在第 6 期已经出现；`validate_result` 是本期新函数。
4. 本期结束后，项目状态变成什么？  
   Agent 可以判断一次模型输出是否符合最小结构。
5. 下一期要承接哪一个未解决问题？  
   校验失败或 API 调用失败时，程序还不知道怎么兜底。

## P013：安全调用模型

1. 上一期最后留下的项目状态是什么？  
   Agent 能检查输出字段，但还没有处理超时、网络错误和失败 fallback。
2. 本期只新增哪一个能力？  
   新增 `safe_call_llm()`，做最小 timeout、retry、fallback，并把失败原因记到 `errors`。
3. 本期出现的函数、变量、文件，前面是否已经讲过？  
   `fake_llm` 和 `summary / concepts / outline` 的结果形状前面讲过；`safe_call_llm`、`retries`、`timeout_seconds`、`errors`、`used_fallback` 是本期新内容。
4. 本期结束后，项目状态变成什么？  
   模型调用失败时，demo 仍然可以返回一个可展示的 fallback result，并保留可解释的错误记录。
5. 下一期要承接哪一个未解决问题？  
   资料来源仍然靠手动粘贴，下一期读取本地 Markdown。

## P014：读取本地 Markdown

1. 上一期最后留下的项目状态是什么？  
   模型调用已经有兜底，但输入资料还没有文件入口。
2. 本期只新增哪一个能力？  
   新增 `read_markdown(file_path)`，只读取本地 `.md` 文件。
3. 本期出现的函数、变量、文件，前面是否已经讲过？  
   本地资料和知识库目标前面讲过；`read_markdown` 和 `file_path` 是本期新内容。
4. 本期结束后，项目状态变成什么？  
   Agent 可以从本地 Markdown 文件拿到资料文本。
5. 下一期要承接哪一个未解决问题？  
   文件变长后，不能把整篇资料都塞给模型，需要先做最小检索。

## P015：关键词分段检索

1. 上一期最后留下的项目状态是什么？  
   Agent 能读取 Markdown，但还不会从长资料里挑重点片段。
2. 本期只新增哪一个能力？  
   新增 `retrieve_chunks(query, text)`，用关键词和分段做最小检索。
3. 本期出现的函数、变量、文件，前面是否已经讲过？  
   `query` 和 `text` 是普通输入；`chunks` 是本期新变量；没有引入向量数据库。
4. 本期结束后，项目状态变成什么？  
   Agent 可以先找相关片段，再准备交给模型回答。
5. 下一期要承接哪一个未解决问题？  
   还没有把 API、读取、检索串成一次完整问答。

## P016：第一次真实资料问答

1. 上一期最后留下的项目状态是什么？  
   已经分别有模型入口、失败兜底、Markdown 读取和本地检索。
2. 本期只新增哪一个能力？  
   新增 `answer_question(question, file_path)`，把前面能力串成一次问答 demo。
3. 本期出现的函数、变量、文件，前面是否已经讲过？  
   `llm_adapter`、`safe_call_llm`、`read_markdown`、`retrieve_chunks` 都已在 P011-P015 出现；`sample_notes.md` 只是演示资料。
4. 本期结束后，项目状态变成什么？  
   项目能跑通“读取资料 -> 检索片段 -> 组装 prompt -> 调模型回答”的最小链路。
5. 下一期要承接哪一个未解决问题？  
   现在工具仍由代码固定调用；后面要讲什么才算 Agent 的工具，以及模型如何决定用哪个工具。

## 给脚本线程的边界提醒

- P011 不讲完整 OpenAI SDK 教程，只讲模型适配器边界和环境变量。
- P012 不讲重试，只讲字段校验。
- P013 不讲结构化输出，只讲调用失败时的 timeout、retry、fallback。
- P014 不讲检索，只讲本地 Markdown 读取。
- P015 不讲向量数据库，只讲关键词和分段检索。
- P016 不新增新技术，只把前 5 期能力串起来。
- 真实 API 具体 SDK 写法需要脚本定稿前再按官方文档确认；当前代码保留安全占位，避免误提交密钥或误产生调用成本。
